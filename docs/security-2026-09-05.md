# DAW credential-hygiene incident audit

Scope: DAW only, based on local `0498d97` and published `7fd5ff3` / `8901a85`. No published history rewrite, rotation, external login attempts, application behavior changes, or push was performed.

## Classification and boundaries

- Reported GitGuardian `Generic Password` location: `compose.yml:8` in DAW-1 `7fd5ff3e60bb4537085f88fe0ed0966dc0f31198`. The complete Compose blob is unchanged at the audit baseline (`37f3795a89ca4b82ef917e0c663687ef2e2fcc1e`). That line contains a required environment-variable expression, not a password literal or fallback. Its diagnostic text cannot become the configured password. Static verdict: no actionable embedded credential at this location. Matching the exact private GitGuardian incident remains pending authenticated dashboard access.
- An additional synthetic credential representation existed at `tests/unit.test.ts:25` in all three local revisions. It is in a deliberately malformed PostgreSQL URL, exclusively used to verify a generic parser error. No database connection or external authentication uses this test value. The fixture now generates its material at runtime and preserves the malformed-host/error assertion.
- README instructions generate local credentials at runtime; PostgreSQL publication is loopback-only. Integration clusters use isolated loopback trust authentication and runtime-generated operator tokens. No tracked dotenv file or local ignored dotenv file was found. No real credential exposure was identified in the inspected content. Repository evidence cannot prove that a person never reused any arbitrary test string in an unrelated external system.
- No `SECURITY.md` policy applied. README, Compose, entry points and test harness establish a production-inspired local showcase, not a production deployment claim.

Docker's [required-variable semantics](https://docs.docker.com/reference/compose-file/interpolation/) distinguish error messages from defaults. `docker compose --env-file NUL config --quiet`, with implicit dotenv loading disabled, rejected an empty variable (exit 1) and accepted a runtime-generated value (exit 0). No service was started or authenticated by this check. Compose remains unchanged.

## Audit coverage and remediation

All three reachable revisions and their tracked content were scanned, including documentation and generated evidence. The broad location-only audit covered 143 unique content blobs. Reflogs contained only the same DAW-1/2/3 progression. The repeatable guard's path/blob history pass covered 146 identities and detected the historical malformed-URL fixture. These are scans of project content, not an exhaustive scan of installed dependencies, tool binaries, ignored runtime databases, or the user's machine.

The separate hygiene change adds `scripts/secret-guard.mjs`, regression tests, `npm run test:secrets`, an early CI gate, and the same gate inside `npm run validate`. Findings contain only file, line, rule and optionally revision, never matched values. Tests construct unsafe fixtures dynamically and cover literal assignments, quoted YAML keys, credential defaults, URL passwords, authorization material, selected provider signatures, private-key markers, dotenv paths and the required Compose contract. The Compose check intentionally pins the existing single inline loopback mapping; it is not a general YAML/security parser.

An independent review reproduced quoted-key and comment-decoy gaps; both were corrected and covered before full validation. No authentication, workflow, worker, lease, fencing, retry or external-effect implementation was changed. The offline guard is bounded hygiene enforcement, not a guarantee of secret absence or a replacement for GitGuardian.
